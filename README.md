# 💰 Wallet & Payment Service v2 (Idempotent Payments)

Модульный сервис цифровых кошельков и финансовых транзакций на Go, спроектированный по принципам **Clean Architecture** с гарантией **идемпотентности запросов (Idempotency Keys)** и защитой от двойных списаний.

---

## 📌 Какая стояла задача и какую боль закрывали

### Проблема (Боль):
В платежных системах и мобильных приложениях критически важна защита от повторных списаний:
- Пользователь нажал кнопку «Оплатить», запрос ушел, но из-за нестабильного мобильного интернета ответ потерялся. Пользователь нажимает кнопку второй раз.
- Если бэкенд не обладает механизмом идемпотентности, со счета дважды спишутся деньги за одну покупку.
- При одновременных операциях списания и пополнения баланса возникают гонки (Race Conditions) и взаимные блокировки (Deadlocks).

### Решение:
- Внедрен механизм **Idempotency Keys**: каждый платежный запрос сопровождается уникальным ключом клиента. Повторный запрос с тем же ключом не выполняет списание заново, а возвращает результат оригинальной транзакции.
- Атомарное изменение баланса кошелька в PostgreSQL с валидацией остатка (`balance >= amount`).
- Чистая архитектура с полной изоляцией доменной модели кошелька (`domain`) от деталей базы данных.
- Поддержка двух реализаций слоя хранения: **PostgreSQL** (продакшн) и **In-Memory** (быстрые изолированные тесты без сторонних сервисов).

## 🏗 Архитектура и схема потоков данных

```
  [ Client / Mobile Request ]
               │
               │ POST /wallets/:id/pay
               │ Header: X-Idempotency-Key
               ▼
  ┌────────────────────────────────────────────────────────┐
  │                  Wallet API Handler                    │
  └──────────────────────────┬─────────────────────────────┘
                             │
                             ▼
  ┌────────────────────────────────────────────────────────┐
  │                 Wallet Domain Service                  │
  │  1. Проверка существования Idempotency Key             │
  │     - Если ключ найден ➔ возвращаем сохраненный ответ  │
  │  2. Валидация достаточности баланса                    │
  └──────────────────────────┬─────────────────────────────┘
                             │
                             ▼
  ┌────────────────────────────────────────────────────────┐
  │         PostgreSQL Transaction (pgxpool)               │
  │  1. SELECT balance FROM wallets FOR UPDATE             │
  │  2. UPDATE wallets SET balance = balance - amount      │
  │  3. INSERT INTO payments (id, wallet_id, amount, ...)  │
  │  4. INSERT INTO idempotency_keys (key, status, body)   │
  └──────────────────────────┬─────────────────────────────┘
                             │
                             ▼
                       [ Commit ]
```

## 🛠 Используемые библиотеки и стек

| Технология | Назначение в проекте |
|---|---|
| **Go 1.23+** | Язык реализации ядра сервиса |
| **`github.com/jackc/pgx/v5`** | Пул соединений и транзакции PostgreSQL с строгим контролем блокировок |
| **`github.com/google/uuid`** | Уникальные идентификаторы кошельков, платежей и идемпотентных ключей |
| **PostgreSQL 16** | Реляционное хранилище со строгой ссылочной целостностью и ACID-гарантиями |
| **Docker Compose** | Локальный подъем базы данных и прогон миграций |

## 📁 Структура проекта

```
.
├── cmd/
│   └── api/                # Инициализация приложения, роутинга и запуск сервера
├── internal/
│   ├── app/                # DI контейнер и сборка компонентов приложения
│   ├── config/             # Конфигурация окружения
│   └── wallet/
│       ├── domain/         # Чистые сущности: Wallet, Payment, ошибки, интерфейсы
│       ├── service/        # Сервисная бизнес-логика и сценарии использования
│       └── repository/
│           ├── postgres/   # Реализация репозитория на PostgreSQL
│           └── memory/     # In-memory mock реализация для тестирования
├── migrations/             # SQL миграции схемы (wallets, payments, idempotency)
├── pkg/
│   └── postgres/           # Обертка над pgxpool с безопасным закрытием
├── docker-compose.yml      # Локальный PostgreSQL 16
└── .env.example            # Пример переменных окружения
```
